### Q2：6 个整数存在哪里？

x86-64 只有 6 个参数寄存器（`rdi`、`rsi`、`rdx`、`rcx`、`r8`、`r9`），第 7、8 个参数要用 `push` 传到栈上。请填表：

| 第几个数 | 栈上地址 | 通过哪个参数传给 `sscanf` |
| --- | --- | --- |
| 1 | `rbp-0x40` | `rdx`（第 3 个参数） |
| 2 | `rbp-0x3c` | `rcx`（第 4 个参数） |
| 3 | `rbp-0x38` | `r8`（第 5 个参数） |
| 4 | `rbp-0x34` | `r9`（第 6 个参数） |
| 5 | `rbp-0x30` | 栈参数，第 7 个（后 push 的那个） |
| 6 | `rbp-0x2c` | 栈参数，第 8 个（先 push 的那个） |

并回答：为什么这些地址相差 4 字节？这说明它们是什么类型、在内存里怎么排？

答：它们是连续的 `uint32_t`（4 字节），在栈上构成数组 `values[0..5]`；地址从低到高对应下标从小到大，即 `&values[i] = rbp - 0x40 + 4*i`。

> 卡点记录：为什么会有两次 `lea ...,%rax`？
>
> `%rax` 被复用了两次，每次 `push` 用的都是它上面最近的那次写入：
> - `40212a: lea -0x2c(%rbp),%rax` 写入的值，被 `402137: push %rax` 用掉；
> - `402138: lea -0x30(%rbp),%rax` 重新写入，被 `402143: push %rax` 用掉。
>
> 所以两次 `lea` 都不是多余的，它们压入的是两个不同的地址。判断寄存器当前的值，永远只看最近一次写入。
>
> 还要记住：push 的顺序与参数顺序相反。栈向下生长，先 push 的落在较高地址，是第 8 个参数；后 push 的落在 `[rsp]`，是第 7 个参数。
>
> 另外一个容易混的点：`rax` 不是"第几个参数"，它只是为了构造要 push 的值而临时使用的寄存器；参数编号要看 `sscanf` 的原型 `sscanf(input, fmt, &v0, &v1, ...)`。
>
> 验证命令（本人已复跑）：
> ```bash
> gdb -batch -ex 'set pagination off' -ex 'break *0x40214e' \
>     -ex 'run --seed 42 --phase 2 < /tmp/six.txt' \
>     -ex 'info registers rdx rcx r8 r9' -ex 'x/2gx $rsp' ./bomb
> ```
> `rdx/rcx/r8/r9` 打印出第 1~4 个数的地址；`x/2gx $rsp` 打出的两个地址依次是第 7、第 8 个参数（即第 5、第 6 个数）。6 个地址应当相差 4 字节且连续。

### Q3：第一个数的公式

对应汇编（`40215a` ~ `40216e`）：

```asm
40215a:	mov    %r13,%rax    # rax = r13
402160:	shr    $0x5,%rax    # rax >>= 5
402164:	add    %eax,%eax    # eax *= 2
402166:	and    $0x7e,%eax   # eax &= 0x7e
402169:	add    $0x1d,%eax   # eax += 0x1d
40216c:	cmp    %eax,%esi
```

提示：`add %eax,%eax` 相当于 `eax = eax * 2`；`and $0x7e` 保留第 1~6 位；`0x1d` = 29。

答（写成 C 表达式）：

`uint32_t(r13 >> 5) * 2 & 0x7e + 0x1d`   ← 运算顺序对，写法要改（见批注）

更正：`(((uint32_t)(r13 >> 5) * 2) & 0x7e) + 0x1d`

✅ 已核对：写进求解函数的形式是 `(((uint32_t)(challenge >> 5) * 2) & 0x7e) + 0x1d`，代入 seed 42 得 145，与 GDB 在 `*0x40216c` 处看到的 `$eax` 一致。
（`r13` 只是分析时的寄存器名，代码里要写成参数名 `challenge`。）

> 批注（Q3）：运算顺序正确（`>>5` → `*2` → `&0x7e` → `+0x1d`），但有两处要修正：
>
> 1. C 的运算符优先级会导致算错。`x * 2 & 0x7e + 0x1d` 会被解析成 `(x*2) & (0x7e + 0x1d)`，因为 `+` 比 `&` 优先级高。seed 42 实测：正确写法得 145，错误写法得 144。
>    C 运算符优先级（高 → 低）：`* / %` → `+ -` → `<< >>` → 比较 → `&` → `^` → `|`。
>    把汇编翻译成 C 时，每一步都加括号最保险——汇编是"按顺序一条条执行"，C 表达式是"按优先级解析"，两者不是一回事。
> 2. `uint32_t(...)` 是 C++ 的函数式转换写法，C 里应写 `(uint32_t)(...)`；另外求解函数里要用参数名 `challenge`，`r13` 只是运行时的寄存器名。
>
> 参考写法：
> ```c
> uint32_t x  = (uint32_t)(challenge >> 5);
> uint32_t v0 = (x * 2 & 0x7e) + 0x1d;      /* 先 (x*2) 和 (x*2)&0x7e，再 +0x1d */
> ```
> 等价变形（可用于交叉验证）：`(x * 2) & 0x7e` 等于 `(x & 0x3f) * 2`。
>
> 自查命令（`$eax` 就是程序算出的期望值）：
> ```bash
> gdb -batch -ex 'set pagination off' -ex 'break *0x40216c' \
>     -ex 'run --seed 42 --phase 2 < /tmp/six.txt' -ex 'p/d $eax' -ex 'p/u $esi' ./bomb
> ```

此处得到第一个数145

### Q4：循环三要素

#### 4.0 先补课：汇编里的循环长什么样

C 里的 `for`/`while` 到了汇编里只剩两种跳转，记住这两句就够用：

| 跳转方向 | 指令 | 含义 |
| --- | --- | --- |
| 往上跳（目标地址 < 当前地址） | `jne` / `jmp` / `jl` | 循环的回边，跳回去继续下一轮 |
| 往下跳（目标地址 > 当前地址） | `je` / `jne` / `jge` | 通常是跳过一段代码（`if` 的 else 分支），不是循环 |

所以找循环的第一步永远是：找往上跳的那条跳转。它跳回的目标，就是循环体的开头。

一个标准的 C 循环：

```c
for (i = 0; i < n; i++) sum += a[i];
```

编译出来长这样（这是 `teaching/02_loop_array.c` 里 `array_sum` 的真实汇编，可以自己 `objdump` 对照）：

```asm
  4011dd:	xor    %eax,%eax          # ← 初始化：sum = 0
  4011e0:	add    (%rdi),%eax        # ┐ 循环体：sum += *p
  4011e2:	add    $0x4,%rdi          # │ 步进：p += 4（指针后移一个元素）
  4011e6:	cmp    %rdx,%rdi          # │ 比较：p 到末尾了吗？
  4011e9:	jne    4011e0             # ┘ 回边：没到就跳回去
```

对照关系（这是本关最该记住的一张表）：

| 循环要素 | 标准写法 | 你的 `phase_02` 里对应哪条 |
| --- | --- | --- |
| 初始化 | 循环前的 `xor`/`mov` | `402170`~`40217a` |
| 循环体 | 回边之间的运算 | `402182`~`4021a1` |
| 步进 | 每轮都执行、改的是"计数器/指针" | `402189: add $0x1,%edi`、`40218c: add $0x4,%rdx` |
| 出口条件 | 回边前那条 `cmp` + 回边指令 | `4021a7: cmp $0x6,%edi` + `4021aa: jne 402182` |

注意 `phase_02` 和标准例子的一个区别：标准例子是"指针比较"（`cmp %rdx,%rdi`），你的这关是"计数器比较"（`cmp $0x6,%edi`）。两种都很常见，看到 `cmp $常数,%寄存器` + 回边，基本就是"跑固定次数"。

```bash

```

challenge 全 0 时，`challenge >> k` 恒为 0，异或和移位都变成常数，递推关系会退化得很简单（例如 `values[i] = 3*values[i-1] + 常数`）。先用它把"递推骨架"看清楚，再回到真实 challenge 确认移位部分，思路会清晰很多。

### Q5：移位量 `cl` 是多少？

```asm
402174:	mov    $0xd,%r8d
40217f:	sub    %edx,%r8d
402182:	lea    (%r8,%rdx,1),%ecx     # cl 就是这里的低 8 位
402190:	shr    %cl,%rax
```

#### 5.0 先补课：`shr %cl,%rax` 是什么

平时见到的移位是 `shr $0x5,%rax`——移多少位写死在指令里。
`shr %cl,%rax` 是变量移位：移多少位由 `cl` 寄存器的值决定。

`cl` 是 `rcx` 的最低 8 位，所以 `cl` 的取值只能是 0~255（再多会被硬件按 64 取模）。

读这种代码的思路是分三步：

1. 找出 `cl` 是怎么算出来的（`ecx` 从哪来）；
2. 把 `cl` 代入，看它每次循环是多少；
3. 回到 `rax`，看移完之后取了哪几位。

#### 5.1 手算：`cl` 的表达式

这三条指令连起来看：

```asm
402174:	mov    $0xd,%r8d          # r8d = 13
40217f:	sub    %edx,%r8d          # r8d = 13 - edx     ← 这条在循环【外面】，只执行一次
402182:	lea    (%r8,%rdx,1),%ecx  # ecx = r8 + rdx     ← 这条在循环【里面】，每轮都执行
```

关键：这两条指令不在同一个"时间点"上。

- `40217f` 在循环之前，只执行一次。设当时 `rdx = A₀`（即 `&values[0]`），那么 `r8d` 从此固定为 `13 - A₀`；
- `402182` 在循环里面，每轮都执行，而此时的 `rdx` 已经变成了 `A₀ + 4×(k-1)`。

代入：

```
ecx = (13 - A₀) + (A₀ + 4(k-1)) = 13 + 4(k-1)
```

注意 `A₀` 确实被抵消了（这就是编译器的用意：把"跟地址有关的部分"在循环外预先减掉，循环里只剩下"跟下标有关的部分"），但剩下的是 `13 + 4(k-1)`，不是常数 13。

> 我一开始也以为"减掉又加回来 = 常数"，是 GDB 实测打了脸。这正是必须用 GDB 验证的原因——手算容易漏掉"哪条指令在循环外、哪条在循环内"。

所以 `cl` 是每轮递增的。至于是 `13 + 4(k-1)` 还是别的，就看你把"第几轮"的 `k` 从 0 还是 1 开始数——用 GDB 实测确认，别猜。

#### 5.2 还要注意：`lea` 用的是自增之前的 `rdx`

```asm
402182:	lea    (%r8,%rdx,1),%ecx   # 用 rdx
402189:	add    $0x1,%edi
40218c:	add    $0x4,%rdx           # rdx 在这里才 +4
402190:	shr    %cl,%rax            # 才用到 cl
```

`add $0x4,%rdx` 在 `lea` 之后，所以 `lea` 拿到的是上一轮结束时的 `rdx`。这种"顺序差一条"是最容易算错的地方，读循环时一定要按地址顺序逐条读，不要跳着看。

### Q6：`xor %edi,%eax` 里的 `edi` 是几？

注意循环体开头有一条 `add $0x1,%edi`，它在 `xor` 之前执行。不要凭直觉，用 GDB 看。

#### 6.0 为什么这里特别容易错

回忆 C 循环：`for (i = 0; i < n; i++)`，`i` 的"第几轮"和"值"差 1。汇编里也一样，计数器先自增、再参与运算和先参与运算、再自增是两种不同的写法，差一位就全错。

你只需要回答一个问题：`add $0x1,%edi` 执行完、`xor %edi,%eax` 执行时，`edi` 是"第几轮"？

- 如果初始化是 `edi = 1`，自增后变 2 → 第 1 轮用 2；
- 如果初始化是 `edi = 0`，自增后变 1 → 第 1 轮用 1。

看初始化那一条 `mov $?,%edi` 就知道了，然后必须用 GDB 实测确认（`printf "edi=%d\n", $edi`）。
